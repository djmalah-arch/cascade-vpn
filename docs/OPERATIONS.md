# Эксплуатация Cascade VPN

Все доступы конкретной установки — в `/root/geovpn-credentials.txt` (выводится установщиком; храните в менеджере паролей).
Ниже `vpn.example.com` — домен входного сервера, команды выполняются на нём из `/opt/cascade-vpn`.

## Доступ и роли

1. Один раз открыть секретную ссылку `https://vpn.example.com/?k=…` (cookie на год) — без неё сайт не открывается.
2. Пароль на экране входа (сессия 12 ч):

| | Администратор | Модератор |
|---|---|---|
| Пользователи | все группы, новые группы, перенос между группами | только группа `work` |
| Серверы и балансировщик | управление | просмотр |
| Панель Remnawave (`/`) | да | нет |

Сменить пароль: `docker exec geovpn-portal geovpn set-password admin|users 'новый'`.

## Архитектура

| Контейнер | Назначение | Порт |
|---|---|---|
| `remnanode` (xray) | VLESS+Reality и Hysteria2; маршрутизация (RU/YouTube напрямую, остальное — на выходы) | 443/tcp, 443/udp |
| `geovpn-caddy` | сайт: портал, страницы, подписки, панель — **за Reality** (посторонние на :443 получают обычный сайт) | 127.0.0.1:8443, 80 |
| `remnawave`, `remnawave-db`, `remnawave-redis` | панель Remnawave (пользователи, подписки, ноды) | 127.0.0.1:3000 |
| `geovpn-awg` + `geovpn-singbox` | AmneziaWG 2.0 (userspace) → TPROXY → xray | UDP (см. доступы) |
| `geovpn-zapret` | обход DPI для YouTube по IPv4 | — |
| `geovpn-mtproxy` | прокси Telegram, секрет на пользователя, выход через туннель | 9443/tcp |
| `geovpn-portal` | админка, страницы, сторож балансировщика, пиры AWG, пользователи MTProxy, мониторинг, бэкапы | 127.0.0.1:8090 |

Профиль xray входного сервера **генерирует портал** (из списка выходов и приоритетов) — ручные правки профиля `MSK` в панели будут затёрты.

## Мониторинг и журнал

- `/admin` → строка «Состояние системы» (ноды, выходы, YouTube, службы, бэкап), по клику — подробности.
- `/admin/servers` → «Журнал»: переключения балансировщика и **критические ошибки** (нода не на связи, выход недоступен,
  служба не работает, YouTube недоступен, сбой установки сервера, сбой действия). Повторы склеиваются «×N».
- Уведомления в Telegram/почту (снаружи РФ): зарегистрируйтесь на healthchecks.io, создайте проверки
  (Period 1 min, Grace 3 min) и впишите их UUID в `data/portal/hc.env`:
  ```
  HC_ALIVE=<uuid>        # входной сервер жив, все службы работают
  HC_YOUTUBE=<uuid>      # YouTube с входного сервера
  HC_EXIT_<ID>=<uuid>    # канал до выхода (ID — как на странице серверов, заглавными)
  ```
  Портал шлёт пульс каждую минуту через соответствующий канал; пропал пульс — healthchecks.io уведомит.

## Сбои

**Выход заблокирован / упал.** Трафик сам уходит на следующий по приоритету: переключает сам xray (резерв — `fallbackTag`
балансировщика), без перезапуска, соединения пользователей не рвутся. Портал перестраивает профиль (это перезапуск xray)
только если недоступны и основной, и резерв, и когда основной вернулся после такой двойной аварии. На `/admin/servers` колонка «Семейства»:
IPv4 «нет», IPv6 «ок» — IPv4 заблокирован в РФ, мост уже по IPv6, можно не трогать; оба «нет» — проверить сервер извне РФ.
Замена: купить новый VPS → «Добавить сервер»; старый → «Удалить…». Сменился IP у хостера → «Адрес…». Клиентам ничего делать не нужно.

**Входной сервер упал.** После перезагрузки Docker поднимет всё сам (`restart: always`). Проверка: `docker compose ps`.

**Входной сервер заблокирован / переезд.** Новый VPS в РФ → перенести `/opt/cascade-vpn/data` из бэкапа →
`./install.sh` (увидит `data/install.env` и возьмёт прежние значения) → сменить A-запись домена.
Файрволы выходов портал обновит сам (ограниченным SSH-ключом, который умеет только менять разрешённый адрес входа);
проверка и ручная рассылка — `/admin/servers`, карточка «Вход MSK». Ссылки пользователей не меняются (везде домен);
Amnezia/Telegram, возможно, придётся переподключить вручную.

**Не работает YouTube.** `docker exec geovpn-portal geovpn status`. По IPv6 должен работать сам; для IPv4 —
подобрать стратегию zapret: `docker exec -it geovpn-zapret bash -c 'cd /opt/zapret && ./blockcheck.sh'`,
вписать строку стратегии в `data/zapret/strategy`, `docker compose restart zapret`.

**Hiddify не подключается по Reality, Happ — да.** Обновился xray: образ ноды закреплён по хэшу (`NODE_IMAGE` в
`docker-compose.yml`) — верните прежний. Xray ≥ 26.9.8 требует от клиентов ML-KEM, который sing-box (Hiddify) пока не шлёт.

**Amnezia подключается, но ничего не грузится.** `docker compose logs awg singbox`; `docker compose restart awg`.
Конфиги со страниц содержат `MTU = 1376` (для мобильных сетей).

## Игры и сервисы мимо VPN

`data/portal/direct.json` — домены, категории geosite и IP-сети (сейчас Steam/Valve/CS2 и STALZONE).
После правки: `docker exec geovpn-portal geovpn apply-direct`. Happ и sing-box-клиенты пускают их напрямую с устройства,
Hiddify/Amnezia — напрямую с входного сервера (без крюка через заграницу). Сети компании удобно брать по её AS:
`https://stat.ripe.net/data/announced-prefixes/data.json?resource=AS<номер>`.

## Бэкапы

Ежедневно ~03:30 МСК в `data/portal/backups` (14 шт.): БД панели, все секреты и состояние портала, ключи и параметры AmneziaWG,
MTProxy, сертификаты. Сейчас: `docker exec geovpn-portal geovpn backup`.
Копия сразу уходит на **выход с наименьшим приоритетом** (не получилось — на следующий) в `/root/geovpn-backups/`
(30 шт.). Пишет её отдельный ключ портала, который умеет только сохранить файл бэкапа. Статус — «Копия на выходе» в
«Состоянии системы». Ключ приёма ставится при добавлении сервера; на выходы, добавленные раньше:
`docker exec -it geovpn-portal geovpn host-extras <id>` (спросит root-пароль). При удалении сервера из портала с паролем
бэкапы с него удаляются. Восстановление: скопировать архив на новый входной сервер, распаковать в `/opt/cascade-vpn/data`.

## Защита серверов

- **fail2ban** на входе и на всех выходах: 5 неверных паролей SSH за 10 минут — бан на час, повторно — дольше (до недели).
  Адрес входа на выходах в исключениях. Разбанить себя: `fail2ban-client set sshd unbanip <ip>`; статус: `fail2ban-client status sshd`.
- `tcp_mtu_probing = 1`: MTU пути вход ↔ выходы 1450, так «большие» пакеты не зависают.
- Клиенты AmneziaWG не видят друг друга и служебные порты входа по туннельному адресу.

## DNS

- xray на входе резолвит домены пользователей через **DoH** (Google 8.8.8.8, запасной — Яндекс 77.88.8.8, в крайнем случае
  системный DNS), с кэшем. Открытых DNS-запросов из российского ДЦ нет; Cloudflare 1.1.1.1 не используется (в РФ медленный).
- Обычные DNS-запросы клиентов на порт 53 (Hiddify, AmneziaWG, любой адрес резолвера) отвечает сам вход — без крюка через выход.
- AmneziaWG: IPv4 и **IPv6** идут в туннель (раньше IPv6 шёл мимо VPN на сетях с IPv6). Старые конфиги работают, но без
  IPv6-туннеля: чтобы получить новый, пользователю нужно заново импортировать конфиг со своей страницы.

## Списки geoip / geosite

Маршрутизация (RU напрямую, YouTube, игры) идёт по спискам Loyalsoldier/v2ray-rules-dat. Портал обновляет их в ноде
**по понедельникам ~04:00 МСК** (проверка sha256, перезапуск xray, откат, если после обновления канал не работает) и
возвращает свежие после пересоздания контейнера ноды. Вручную: `docker exec geovpn-portal geovpn geo-update`.

## Обновление

```bash
cd /opt/cascade-vpn && git pull && docker compose build && docker compose up -d
```
Все образы закреплены (версия + хэш) в `docker-compose.yml`, сами они не обновятся. Обновляйте осознанно: поменять хэш,
проверить, закоммитить (особенно ноду xray — см. «Hiddify не подключается»).
