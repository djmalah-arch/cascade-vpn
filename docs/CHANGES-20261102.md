# Исправления и проверка, 02.11.2026

## Порядок работы (ub-mode)

1. Воспроизведены утечка приглашения чужой группы, пропуск повторного AWG apply, использование выключенного pin и порядок private/UDP-правил.
2. Закрыта проверка группы; операции создания и отзыва получили сохраняемый intent и повторную синхронизацию. MTProxy закрывает только сеансы с удалённым или заменённым секретом.
3. Запись JSON вынесена в общий модуль: межпроцессный reentrant lock, уникальный временный файл, fsync и atomic replace. Версия маршрутизации защищает от применения старого снимка сторожа.
4. Публичные страницы отделены в контейнер без сети и привилегий. Доступ Caddy — через Unix-сокет; административные файлы в контейнер не передаются. Снимок данных имеет ограниченный срок действия.
5. Установщик получил закреплённый образец окружения, буквальную запись паролей, возобновляемый bootstrap и восстановление PostgreSQL перед запуском панели.
6. Введён переносимый backup v2 и запрет перезаписи существующей установки. Реальная проверка выявила старый формат имени в оффсайт-приёмнике; приёмник обновлён с проверкой SHA-256 и размера.
7. Созданы общий генератор правил, импорт редактируемых исключений direct.json и интерфейс управления. Перед применением профиль проходит xray run -test.
8. Реализованы настоящие протокольные клиенты и контроль сайтов. Данные без доказательства не помечаются подтверждёнными.
9. Интерфейс переведён на нейтральный графит: видимая форма создания, действия по клику на пользователя, сохранение ввода при автообновлении, диалоги и свёрнутые технические блоки.

## Валидация

Итоговый набор — 31 регрессионный тест (Unix-socket тест выполняется в Linux). На рабочем сервисе подтверждены
оба направления IPv4 и зарубежный IPv6 для Reality, HY2 и AWG. Для 22 из 22 контрольных сайтов подтверждён ожидаемый
маршрут; ответы HTTP с ограничениями сервиса не смешиваются с ошибками маршрутизации. Реальное восстановление backup v2
в изолированную PostgreSQL восстановило все 37 таблиц. Временные пользователи, клиенты и тестовая БД удаляются после проверки.

- Регрессионные unit-тесты запускаются в Python на Windows и в Linux-образе проекта; Unix-сокет проверяется в Linux.
- Браузерные проверки охватывают desktop/mobile, модальные окна, поиск и сохранение ввода при обновлении.
- На работающем сервисе проверяются роли и полный жизненный цикл временного пользователя с последующим удалением.
- Контроль IPv4/IPv6 выполняется реальными Reality/HY2/AWG-клиентами, а не только общим SOCKS-monitor inbound.
- Backup v2 проверяется распаковкой и импортом в отдельную PostgreSQL без сети; временная БД удаляется.
- Чистая установка новой ОС не выполняется на рабочем VPS; для неё проверяются bootstrap, восстановление, Compose, shell-синтаксис и совместимость конфигурации с используемым Xray.

## Эксплуатационные замечания

Изменение профиля или geo-файлов может прервать текущие соединения. Проверка трафика сама профиль не меняет.
При первом обновлении прежние исключения импортируются с сохранением игровых маршрутов Happ; это однократная миграция.
Первое SSH-подключение использует пароль и сохраняет host key; для проверки первой связи можно указать SHA256-отпечаток хостера.
Автоматические подключения проверяют сохранённые ключи и отказываются от неизвестного или изменённого сервера.
