# Проверка действующей маршрутизации

Схема эксплуатации сохраняет один вход MSK. При блокировке провайдер меняет IP, оператор обновляет A/AAAA. Допустимый перерыв до двух часов. Диагностика выполняется из MSK.

| Политика | Состояние и вывод |
|---|---|
| Российские сайты и сети | `geosite:category-ru` и `geoip:ru` ведут на `direct-ru`. Все восемь проверенных доменов получили этот outbound. Список наблюдения — выборка, базовое правило охватывает дополнительные сайты. |
| Пользовательские исключения | 37 включённых правил из `direct.json`. 18 доменов Steam/Valve/CS2, STALCRAFT/STALZONE и War Thunder, 17 подсетей, категория `steam` и один диапазон UDP. Все идут напрямую с MSK при попадании трафика на сервер. Импортированные исключения могут идти с устройства в Happ. |
| Игровые исключения | В профиле 40 правил `direct`, включая 37 отдельных и три сводных повтора. Повторы можно убрать после проверки эквивалентности порядка. UDP 19000–20999 совпадает по порту без привязки к адресу и может захватывать другой UDP-трафик. Сузить по фактическим адресам игровых серверов после теста игр. |
| YouTube и DNS | YouTube отправляется в `yt-dpi`, его UDP/443 блокируется. DNS на 53 перехватывается отдельным правилом. Частные сети и BitTorrent имеют отдельные блокирующие правила. |
| OpenAI | `geosite:openai` закреплён за ServForTest1. Для `chatgpt.com` и `openai.com` подтверждён `x-servfort-4`, оба ответили 403 на диагностический HEAD. Это подтверждает выбор выхода. Проверка входа в аккаунт требует клиентской сессии. |
| Остальные зарубежные | Общий балансировщик, текущий основной выход coldrese. Для остальных 18 контрольных сайтов подтверждён `x-coldrese-6`. |

На реальном прогоне Reality, Hysteria2 и AWG показали ожидаемые российский и зарубежный IP, а также IPv6. Через Reality все 28 из 28 сайтов выбрали ожидаемый маршрут. HTTP HEAD проверяет первый ответ сайта. Отдельный GET с переходом по ссылкам через MSK показал 429 после перенаправления Avito, пять перенаправлений Ozon без конечного ответа 2xx, отсутствие ответа HTTPS у Сбера и Почты за время проверки. Для Avito и банков при необходимости предпочтительна маршрутизация напрямую с абонентского устройства там, где клиент поддерживает исключения.

## Правки и следующий этап

- Повтор доставки IP хранит список выходов, которые ещё не подтвердили обновление. Сменившийся IP применяется ко всем выходам, повтор — к оставшимся. Снимок правил обновляется вместе с ревизией. Нерабочий адрес резерва заменяется при наличии проверяемой альтернативы.
- Пароль роли входит в подпись сессии через сохранённый хеш. Смена пароля сразу отзывает сессии этой роли. IPv4 и IPv6 `FORWARD` из AWG запрещён; корректно перехваченные соединения проходят через локальный `INPUT`.
- Для перехода SSH на ключи нужно установить ключ оператора, проверить вторую независимую сессию и аварийный вход. Действия с уже развёрнутыми выходами сейчас могут принимать root-пароль через админку. Заменить их отдельными ограниченными командами обслуживания до выключения пароля на выходах.
- Портал использует Docker для проверки Xray, бэкапов, сигналов MTProxy, диагностических контейнеров, чтения журнала и переноса образов. Для удаления сокета нужен отдельный исполнитель с фиксированными типами операций. Запрет произвольных контейнеров, команд, bind mounts и файловых путей проверять тестами границы полномочий. Обычный socket proxy с открытыми `exec` и `create` оставил бы возможность обойти ограничения.
